# 管理后台 Admin UI 实施计划

> **For Hermes:** 使用 subagent-driven-development 技能按任务逐一实现本计划。
> 本计划仅规划,不执行。配套:docs/03-API契约与扩展性设计.md(信封/错误码/扩展规范)。

**Goal:** 为 jieqi_backend 构建最高权限管理后台:全局配置控制 + 数据管理(用户/作物/道具/定价/节气)+ 内嵌 PowerShell 终端(可启停服务器),UI 简洁美观(节气主题)。

**Architecture:** FastAPI 静态托管单页应用(原生 HTML/CSS/JS,无构建步骤),新增 `/v1/admin/*` 管理 API(独立 admin JWT 鉴权),WebSocket 终端桥(ConPTY + PowerShell,xterm.js 前端)。设计采用 popular-web-designs 的 **Supabase 深色翡翠绿**设计系统(与"节气/种田/终端"气质契合)。

**Tech Stack:** FastAPI(现有)+ 原生 HTML/CSS/JS + xterm.js(本地 vendor)+ pywinpty(ConPTY)+ WebSocket。

## 1. 现状与假设

- 现有 `server/` 骨架:P0 已上线(认证/农场/节气轮转/商店道具/调试接口),测试通过,已推送 GitHub。
- 已有 `game_config` KV 表(热更新)、`crops`/`items` 配置表、`term_config`/`game_clock`、`users`/`players`。
- 现有 `/v1/debug/*` 调试接口(DEBUG_ENABLED 控制)—— 管理后台将提供更完整的 admin 域,debug 接口保留。

## 2. 板块设计(后台页面结构)

| 板块 | 内容 | 对应 API |
|---|---|---|
| ① 仪表盘 Dashboard | 服务状态(PID/启动时间/版本)、当前节气+剩余秒、用户数/农场数、金币总量、数据库大小 | `GET /v1/admin/dashboard` |
| ② 用户列表 Users | 分页列表(名字/IP/等级/金币/状态)、封禁/解封、查看档案 | `GET /v1/admin/users`、`PATCH /v1/admin/users/{id}/status` |
| ③ 全局配置 Config | **环境变量/全局变量**:`game_config` KV 列表、新增/编辑/删除、热更新;下方只读展示系统环境变量 | `GET/PUT/DELETE /v1/admin/config*` |
| ④ 作物管理 Crops | 列表 + **新增植物** + 编辑(节气窗 start/end/grace、生长时长、产量、单价、描述)+ 软删除;新增时可选**自动创建对应种子道具** | `GET/POST/PUT/DELETE /v1/admin/crops*` |
| ⑤ 道具管理 Items | 道具列表 + 新增/编辑(名称/分类/效果 JSON/买价/卖价)+ 软删除 | `GET/POST/PUT/DELETE /v1/admin/items*` |
| ⑥ 定价 Pricing | 作物售价 + 道具买卖价统一视图,内联编辑(写同一字段,静态价原则不变) | 复用 crops/items API |
| ⑦ 节气设置 Terms | 24 节气时长列表(默认 300s,可逐节气调整)、游戏时钟(epoch/倍速/暂停)、手动推进 | `GET/PUT /v1/admin/terms*`、`PUT /v1/admin/clock` |
| ⑧ 终端 Terminal | **底部固定栏**(可折叠):内嵌 PowerShell(xterm.js),快捷按钮:启动后端 / 停止后端 / 清屏 | `WS /v1/admin/terminal` |

## 3. 安全模型(最高控制权,必须设防)

- 登录:`POST /v1/admin/login {username, password}` → 独立 admin JWT(与玩家 JWT 同算法不同 role claim,短过期 2h)。
- 守卫:所有 `/v1/admin/*`(含 WS)依赖 `get_current_admin`,无 token 一律 401。
- 终端 = 远程代码执行:仅 demo 开启;`ADMIN_ENABLED=false` 整体关闭;管理员操作(配置/删改/终端命令)写入 `event_logs`(reason=admin_action)。
- 环境变量:`ADMIN_USERNAME`(默认 `admin`)、`ADMIN_PASSWORD`(必填,无默认)、`ADMIN_ENABLED`(默认 true)。

## 6. API 设计(遵循 03 文档信封规范)

```text
POST   /v1/admin/login                       {username, password} → {token}
GET    /v1/admin/dashboard                   → 服务状态/节气/统计
GET    /v1/admin/users?page&page_size        → 用户分页(含玩家档案)
PATCH  /v1/admin/users/{id}/status           {status: 0|1} 封禁/解封
GET    /v1/admin/config                      → 全部 game_config KV
PUT    /v1/admin/config/{key}                {value} upsert
DELETE /v1/admin/config/{key}
GET    /v1/admin/crops                       → 作物列表(含窗口)
POST   /v1/admin/crops                       {name, category, sow_window, grow_seconds, yield_base, base_price, description, auto_seed?}
PUT    /v1/admin/crops/{id}                  编辑(全部字段)
DELETE /v1/admin/crops/{id}                  软删(active=false)
GET    /v1/admin/items · POST · PUT · DELETE 同 crops 模式
GET    /v1/admin/terms                       → 24 节气 + 时长
PUT    /v1/admin/terms/{term_index}          {duration_seconds}
PUT    /v1/admin/clock                       {time_scale?, paused?, reset_epoch?}
WS     /v1/admin/terminal                    ConPTY PowerShell(admin JWT 查询参数鉴权)
GET    /admin                                → 静态页 admin.html
```

错误码沿用现有体系:`10002` UNAUTHORIZED / `30001` ADMIN_BAD_CREDENTIALS / `30002` ADMIN_DISABLED。

## 9. 风险与开放问题

| 风险/问题 | 处理 |
|---|---|
| pywinpty/ConPTY 在部分 Windows 版本不可用 | 终端桥独立模块,import 失败时 UI 显示"终端不可用",不影响其他板块 |
| 终端 = 最高权限 RCE | ADMIN_ENABLED 开关 + 强密码 + 操作审计;生产默认关闭 |
| xterm.js CDN 被墙 | 本地 vendor(npmmirror 下载),零外部依赖 |
| Inter 不支持中文 | 字体栈回退 PingFang SC/微软雅黑 |
| 定价与作物/道具价格字段重复 | 单一数据源:都写 crops.base_price / items.buy_price,sell_price,定价板块只是便捷视图 |
| 系统环境变量展示范围 | 只读展示管理员关心的键(过滤敏感值,如 password/secret 打码) |
| 终端会话模型 | 默认单例共享会话(服务级);若需多管理员并发,改为每连接独立会话(开放问题,默认前者) |
