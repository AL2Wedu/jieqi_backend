# 背包接口定制化改造计划(查询参数化 + 现状性能审计)

> **For Hermes:** 按本计划 TDD 逐任务执行,每任务提交。

**Goal:** 把 `GET /v1/player/inventory` 从"无参全量返回"改造成**可定制化查询**(过滤/搜索/排序/分页/精简视图),例如 `?has_stock=true&category=seed&sort=quantity&order=desc` 只返回有货的种子。

**Architecture:** 保持响应信封与现有字段(只加不减),查询参数全部可选、无参时行为与现状兼容;`inventory_service.list_inventory` 改为 join `Item` 后动态过滤/排序/分页;DB 层**不动**(现状已够快,见性能实测)。

**Tech Stack:** FastAPI Query 参数 / SQLAlchemy 2 join + 动态 where / pytest(TDD)/ 现有 envelope 约定

---

## 1. 现状审计(已实测)

### 1.1 数据库结构

| 表 | 设计 | 索引 |
|---|---|---|
| `user_items` | 复合主键 `(player_id, item_id)` + `quantity` + `extra` + `updated_at` | PK 即索引:player 查询直接走前缀 ✓ |
| `items` | `id` PK、`code` unique、`category/stackable/sell_price/unlock_level/active/sort_order` | code unique 索引;其余无(表小,无需) |
| `item_transactions` | 账本 | `(player_id, created_at desc)` ✓ 已有 |

### 1.2 当前查询与速度实测(dev.db)

```sql
SELECT * FROM user_items WHERE player_id = ?      -- 一次 in_ 加载 item 定义
```

- **实测耗时:0.746 ms**(0 行);EXPLAIN:`SEARCH user_items USING INDEX sqlite_autoindex_user_items_1 (player_id=?)` → **走复合主键索引**
- 行数上限 = 道具目录数(当前 18,未来 30-50),单玩家查询**亚毫秒级,无性能瓶颈**
- **真正的痛点不是速度,是接口能力**:① 永远全量返回(含 quantity=0 的行);② 无过滤/排序/分页参数,客户端每次全量拉取后自己过滤;③ 目录增长后浪费流量

### 1.3 道具可卖性现状

- 18 个道具 `sell_price` **全部 > 0**(含种子,如 seed_shuidao sell=5)→ "可卖"过滤当前区分度为 0,但语义正确,未来目录出现不可卖道具时生效

## 2. 方案:查询参数设计(全部可选)

### 2.1 参数总表

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `has_stock` | bool | false | `true` = 只返回 quantity>0 的行(最实用) |
| `category` | str | 无 | 按道具分类精确匹配(seed/tool/…,取 `Item.category`) |
| `sellable` | bool | false | `true` = 只返回 `sell_price > 0` 的道具(可卖) |
| `stackable` | bool | 无 | 按可堆叠性过滤 |
| `q` | str | 无 | `code` 或 `name` 模糊搜索(`LIKE %q%`) |
| `active` | bool | 无 | 不过滤(兼容现状);显式 `true/false` 收紧 |
| `sort` | str | `sort_order` | `sort_order` / `quantity` / `updated_at` / `code` / `name` |
| `order` | str | `asc` | `asc` / `desc` |
| `page` / `page_size` | int | 无 | 显式传 `page` 才分页(背包行数小,默认不分页);`page_size` 默认 20,≤100 |
| `view` | str | `full` | `full`(现状字段)/ `compact`(只 `item_id/code/quantity`,省流量) |

### 2.2 响应兼容(只加不减)

- 无参数调用:行为与现状一致(返回全部行含 0 数量;排序改为稳定的 `sort_order asc` —— 现状为主键序,文档注明)
- 分页时 `data` 在 `items` 基础上**新增** `page / page_size / total`(第 2.4 节分页信封约定)
- `compact` 视图:items 元素只含 `item_id/code/quantity`
- 现有字段(`quantity` 含 0、`effect` 等)不变,现有客户端不受破坏

### 2.3 示例

```
GET /v1/player/inventory?has_stock=true&category=seed&sort=quantity&order=desc
GET /v1/player/inventory?sellable=true&page=1&page_size=10
GET /v1/player/inventory?q=shui&view=compact
```

### Task 2: service 重构(join + 动态过滤/排序/分页)

**Files:**
- Modify: `server/app/services/inventory_service.py:10-26`(`list_inventory` 重写)

```python
def list_inventory(db, player, *, has_stock=False, category=None, sellable=False,
                   stackable=None, q=None, active=None, sort="sort_order",
                   order="asc", page=None, page_size=20, view="full") -> dict:
    qs = db.query(UserItem, Item).join(Item, Item.id == UserItem.item_id)
    qs = qs.filter(UserItem.player_id == player.id)
    if has_stock:
        qs = qs.filter(UserItem.quantity > 0)
    if category:
        qs = qs.filter(Item.category == category)
    if sellable:
        qs = qs.filter(Item.sell_price.isnot(None), Item.sell_price > 0)
    if stackable is not None:
        qs = qs.filter(Item.stackable.is_(stackable))
    if active is not None:
        qs = qs.filter(Item.active.is_(active))
    if q:
        like = f"%{q}%"
        qs = qs.filter(or_(Item.code.like(like), Item.name.like(like)))
    sort_col = {"sort_order": Item.sort_order, "quantity": UserItem.quantity,
                "updated_at": UserItem.updated_at, "code": Item.code,
                "name": Item.name}.get(sort, Item.sort_order)
    qs = qs.order_by(sort_col.desc() if order == "desc" else sort_col.asc())
    total = qs.count()
    if page is not None:
        qs = qs.offset((page - 1) * page_size).limit(page_size)
    rows = qs.all()
    items = [{"item_id": str(r[0].item_id), "code": r[1].code, "quantity": r[0].quantity,
              **({} if view == "compact" else {"name": r[1].name, "category": r[1].category,
                   "effect": r[1].effect})} for r in rows]
    out = {"items": items}
    if page is not None:
        out.update({"page": page, "page_size": page_size, "total": total})
    return out
```

> 注:`full` 视图字段与现状完全一致(item_id/code/name/category/quantity/effect),现客户端零改动。

## 6. 风险、权衡与开放问题

| 项 | 说明 |
|---|---|
| "可卖"定义 | 建议 `sell_price > 0`(简单、语义正);当前 18 道具全可卖,区分度 0 —— 要不要加"排除种子"?(默认不做,等你拍板) |
| 默认分页? | 建议**默认不分页**(背包行数小),显式 `page` 才分页 —— 避免破坏现有客户端解析 |
| 无参排序变化 | 现状主键序 → 改为稳定 `sort_order asc`,文档注明;若你要求绝对不变,可保留主键序(不建议) |
| 全量含 0 行 | `has_stock` 是缓解;彻底去掉 0 行会破坏现有客户端,故保留默认行为 |

**验收标准**:`GET /v1/player/inventory?has_stock=true&category=seed&sort=quantity&order=desc` 返回正确过滤+排序;无参调用与改造前响应一致;全套测试 + 三查全绿。
